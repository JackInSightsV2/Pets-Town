# Local bridge and launcher implementation

Implemented a loopback-only Node HTTP bridge in `src/server/server.ts` with ephemeral-port test support, snapshot, named `office` SSE events, epoch/sequence replay, explicit snapshot-required 409 on replay gaps, health discovery, and presentation-only actions. Presentation reset never clears pending requests. Replies remain unsupported (501), including when an adapter advertises unverified capability.

Adapter seam: `src/server/adapter.ts` exports `OfficeAdapter` with `initialSnapshot(): OfficeSnapshot | Promise<OfficeSnapshot>`, `subscribe(listener: (event: OfficeEvent) => void): () => void`, and `stop(): void | Promise<void>`. Bridge overwrites adapter sequence/epoch with bridge ordering and deduplicates stable event IDs. Module loader accepts `--adapter <path-or-package>` or `PETSTOWN_ADAPTER_MODULE`; module exports `createAdapter` or a default factory/object. No adapter means empty unsupported data. Explicit `--fixture` provides labelled deterministic development agents/activity/request and no fabricated pet imagery.

`npm run office -- --no-open` owns bridge lifecycle in the foreground, reuses a recognized same-mode service, rejects occupied unrelated ports without terminating anything, and closes a newly created bridge if browser opening fails. `--port` defaults to 4317. `src/server/main.ts` is the dev bridge entry; `scripts/dev.ts` optionally starts bridge + Vite under one parent. Vite `/api` proxy must preserve request Host (default changeOrigin false) so Origin checks work. Static serving permits dist files confined by realpath plus the specific approved office PNG route.

Verification: `tsx --test src/server/server.test.ts` passed five tests covering unsupported empty state, shutdown, origin/token/host checks, presentation idempotency, request persistence (including IDs with unavailable details), exact external resolution, malformed-event rejection, fixture provenance, SSE replay/gaps/epochs, and static symlink/path traversal. `tsc --noEmit` passed. These automated fixtures are not live adapter or browser acceptance evidence. S3 remains pending real pending/resolved-request verification.

## Adapter integration and genuine fixture artwork

Run `npm run office -- --adapter ./src/adapter/index.ts` (or the actual module exporting `createAdapter`) to use a live observer. Adapter event payloads must satisfy `src/shared/contract.ts`, including nullable unknown fields, ISO timestamps, stable event IDs and the source provenance. The bridge validates consumed fields and JSON serializability before applying an event. Rejected observations increment `GET /api/health`'s `adapterErrors`, publish an explicit connection warning, and preserve agent/request state. Adapter subscription cleanup and `stop()` run when the bridge shuts down. No execution control methods are exposed.

`npm run office -- --fixture` now uses the official built-in pet descriptors from `src/shared/pets.ts`, with stable assignments to the three synthetic agents. Fixture provenance remains visible and all trace events are source `fixture`. Starting from the initial two-project snapshot and unresolved child request, the single deterministic trace emits at two-second intervals: editing activity, synthetic handoff, exact external request resolution, work completion, idle state, simulated disconnection, simulated reconnection. It runs once per bridge start and never represents live evidence.

For an approved local copy, the factory accepts `petAssetFiles: { [assetId]: absoluteFilePath }`. Only exact IDs in this allowlist are served under `/pet-assets/:id`; matching snapshot pet URLs are rewritten. This option neither downloads files nor opens arbitrary directories. Production defaults retain official CDN URLs.

Additional verification: seven server tests pass, including official asset assignments, full fixture trace, malformed-event observability, circular-data rejection and explicit local-asset allowlisting. Full TypeScript check encountered concurrent client validation errors (`src/client/validation.ts` unknown `row`/`frames`); no server TypeScript errors were reported in that run.

Review fixes: mismatched request owners cannot clear another agent's request. Subscribe begins before the asynchronous initial snapshot, buffering observations and discarding only buffered events covered by that snapshot's adapter epoch/cursor. Explicit adapter requests reject uncertain launcher reuse. Pet descriptors are restricted to the verified built-in manifest or explicit local file allowlist. Combined dev rejects nondefault proxy ports instead of silently routing to the wrong bridge. Two targeted request-owner/bootstrap regressions passed; broad test runs paused per time constraint.
